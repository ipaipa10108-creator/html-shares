🛡️ MCP 很方便，但你真的敢讓 Agent 隨便 call 嗎？

[!WARNING]
MCP 解決了 Agent「怎麼連到工具」，卻不等同於解決了 Agent「這一次到底能不能執行」。

🧵 MCP：讓 Agent 能「到」工具的地方

MCP（Model Context Protocol）正在快速成為 Agent 連接外部工具的重要標準。

  • 支援平台：Claude Desktop、Cursor、Claude Code、Gemini CLI、Copilot CLI…
  • 功能廣泛：Agent 可透過 MCP 讀檔案、查資料庫、操作 GitHub、呼叫 API，甚至執行系統操作。

[!NOTE]
關鍵問題：MCP 僅解決了「連接」，未保證「執行」的安全性。

🧨 攻擊已經來了：MCP 生態面臨的威脅

近期 MCP 生態系陸續曝現多種攻擊與漏洞：

攻擊類型 描述
惡意 MCP Server / 供應鏈攻擊 偽裝成正常工具，等 Agent 完成數次正常操作後才觸發惡意 payload。
Prompt / Tool Poisoning 利用工具描述、PR 內容等資料，影響模型決策，誘導 Agent 執行不當 Action。
SSRF、Path Traversal、Command Injection、RCE MCP Server 或依賴元件漏洞，使 Agent 成為攻擊鏈一環。

[!IMPORTANT]
共通點：攻擊者最終目標皆為讓某個「Action」真正發生。

🔍 真正的 Execution Boundary

Agent Reasoning → Tool Call → 【Execution Boundary】 → 系統 / API / 檔案 / 資源

[!TIP]
防守重點不在「Agent」，而在「Execution Boundary」這條線上。

🛡️ DROS VajraClaw：在執行邊界設下真正的 Gate

[!CAUTION]
DROS 不試圖教 Agent「不要做壞事」。
因為我們知道：Agent 可能被攻擊、被欺騙、甚至被攻陷。

⚙️ 工程師如何使用 DROS？

[!TIP]
無需重寫 MCP Server 或在每個 Agent Framework 中重複實作 Authorization。

🛠️ 快速上手流程

  1. 啟動 DROS Gateway
  2. 定義 Vajra Policy
  3. 將 Agent 的 MCP Tool Call 經過 DROS 進行執行治理

📋 執行治理流程

Principal → Authorization → Tool/Action Binding → Policy Gate → Execution → Audit → Revocation/Expiry

[!NOTE]
這就是 Agent Security 最終必須補上的那一層：從「治理 Agent」走向「治理 Agent 的 Execution」。

🧠 一句話總結

[!IMPORTANT]
MCP 解決的是：Agent 怎麼使用工具。
DROS 解決的是：Agent 想使用工具時，這一次到底能不能執行。

  • MCP 負責連接
  • DROS 負責執行治理
  • 兩者不是競爭關係，而是互補

[!CAUTION]
當 Agentic AI 真正進入企業、雲端、Code、Browser、IoT 與 Physical AI 時，最終一定會碰到 Execution Boundary。
問題只是：你要不要在那裡放一道真正的 Gate。
